# PRE-REGISTRATION — H2: does routing track the DATA's decomposition?

Written **before any CFOP model is trained**. Governed by the same L1–L4 framework as
`PREREGISTRATION.md` (`dc0cf984`); deviations are enumerated below and justified structurally,
not by convenience.

---

## 1. Hypothesis

**H2 — routing tracks the decomposition *present in the training data*, not a fixed property of
the cube.**

Kociemba solutions carry a 2-phase decomposition (entry into G1). CFOP solutions carry a 4-stage one
(cross → F2L → OLL → PLL). Both are decompositions *of the same domain*, so a model that routes on
whichever one generated its data is tracking the data; a model that routes on G1 regardless is
tracking the cube.

### Primary endpoint: the 2x2 cross-evaluation

Both label functions are computable on **either** dataset — G1 membership is a state predicate, and
so are the CFOP stage predicates (`probe/cfop.py`). So each trained model is scored against **both**
decompositions:

| model trained on | vs CFOP stage | vs G1 phase | H2 predicts |
|---|---|---|---|
| Kociemba (existing, seeds 20–24) | low | **high** (measured: 92% of ceiling) | already satisfied |
| **CFOP (new, seeds 40–44)** | **high** | low | **the test** |

**H2 is SUPPORTED iff**, for the CFOP-trained models,
`cond_NMI(expert; CFOP stage | position)` exceeds `cond_NMI(expert; G1 phase | position)`
in **≥4/5 seeds** AND the paired t-test gives **p < 0.05** in that direction.

**H2 is REJECTED** if the inequality reverses in ≥4/5 seeds — i.e. a CFOP-trained router still
partitions on G1 rather than on the stages its data was built from.

The Kociemba row is computed from **existing checkpoints at no additional cost** and is reported as
the mirror comparison. It is not a free pass: if the Kociemba models also align with CFOP stages as
strongly as with G1, the decompositions are not separable in this domain and H2 is untestable here —
that outcome is declared in advance as **inconclusive**, not as support.

## 2. Declared structural differences from the Kociemba setup

These are properties of CFOP, established by measurement before any model was trained. They are
**not** defects to be fixed, and they weaken what H2 can claim.

1. **Stage is a CONSTRUCTION property, not a state property.** Labelling each move by
   `stage_of(state)` fails monotonicity in **200/200** generated solves, because F2L insertions and
   OLL/PLL algorithms deliberately break earlier stages and restore them. Kociemba's phase was
   monotone in **0/300** violations. Stage labels are therefore **which segment of the solve a move
   belongs to**, verified by the defining predicate holding at each segment end (**300/300**:
   cross_done, f2l_done, oll_done, pll_done).
2. **CFOP is not state-Markovian.** The same cube state occurring mid-`Sune` and mid-`T-perm`
   requires different next moves. Measured conflict rate for a state-only policy: **6.49%** after
   canonicalisation (9.79% before). Kociemba was **0%** by construction.
3. **Consequence: the position-blind arm (C) is dropped** — it is ill-posed here, facing a ~6.5%
   irreducible error floor. This is a structural exclusion, not a budget one. **Arm A only.**
4. **Case coverage is non-canonical.** The generator composes 3 OLL + 4 PLL verified base
   algorithms, reaching 148 OLL and 179 PLL canonical cases rather than the human 57 + 21. The
   decomposition is genuine; the case *distribution* is not human-realistic.

## 3. Data

- **10,000 CFOP solves**, generated by verified reverse construction (`probe/cfop_gen2.py`),
  every case solved by its **one canonical maneuver** (`data/cfop_canon.pkl`).
- **Step-matched to the Kociemba set**, not solve-matched: CFOP solutions are ~55–61 moves vs
  Kociemba's 20.6, so 10k CFOP solves ≈ 550k steps ≈ the Kociemba 25k set's 514k. Matching on
  *steps* keeps the training budget and the conditional-NMI sample size comparable; matching on
  solves would not.
- 90/10 split **by solve**, with the tail-leakage replicate at N=3 and N=6 as before.

### QA gates (replacing the Kociemba set where structurally required)
| gate | status |
|---|---|
| maneuver replays to solved | **kept** (verified 300/300) |
| every state passes `verify()` | kept |
| boundary predicate holds at each segment end | **NEW — replaces the monotonicity gate** |
| `in_G1` monotone | **REMOVED** — meaningless for CFOP |
| state-only label conflict rate | **NEW — reported, not gated** (expected ~6.5%) |
| no duplicate scrambles | kept |
| stage balance, per-stage move histograms | kept |

## 4. Legs, generalised to 4 classes

- **L1 learning gate.** `acc >= 1.30 x majority|(stage, position)` AND `probe >= 0.85` in ≥4/5 seeds.
  The probe is now **4-way** (multinomial logistic regression), so 0.85 is a much stronger bar than
  in the binary case; chance is 0.25 rather than 0.5.
- **L2 router vs nulls.** `cond_NMI(top-1 expert; stage | position)`, row-count-weighted within
  strata. NMI is defined for 4 classes unchanged. Nulls: shuffled router, synthetic position-only
  router, trained hash twin, within-stratum permutation (200 draws). Pass as in A1.1.
- **L3 change-point.** With 4 stages this needs **3** jointly-fitted change points. Given that this
  statistic already false-positived on a pure position router (+0.443, p=0.005) at low boundary
  variance and proved structurally unsuited to history-free models, it is **REPORTED BUT NOT
  REQUIRED** for H2. Recorded here, before results.
- **L4 causal.** `e1` is selected **per stage**: for stage s, the expert maximising
  `P(stage=s | top-1 expert)` among experts holding ≥50 held-out rows. For each stage, force all
  stage-s prediction positions to each expert in turn; `L_s(e) = acc_base(s) − acc_forced(s, e)`.
  **Readout is next-move ACCURACY, not G1-legal mass** — measured: CFOP stages have no move-set
  restriction, and a support-based readout separates {cross,F2L} from {OLL,PLL} but cannot separate
  cross from F2L (TV 0.184) or OLL from PLL (TV 0.190). Accuracy applies uniformly to all four.
  Effect = `L_s(e1_s) / median_{e≠e1_s} L_s(e)`, with the Amendment-1 rule: quote the ratio only
  when the denominator > 0.001, else report absolute `L_s(e1_s)`.
- **Concentration index**, per stage, with the A4.3 floor (Σ_e L_s(e) < 0.05 → undefined) and
  `max_e L_s(e)` reported beside it.

## 5. Scale and seeds
4 layers / d=128, 10k solves, **seeds 40–44** (never used), plus 5 hash twins. Local MPS,
~2.6h total. Declared as small; H2 is tested at the confirmatory scale, not the replication scale.

## 6. What would falsify H2
A CFOP-trained router whose expert partition aligns with **G1 phase** at least as strongly as with
**CFOP stage**. That would mean routing follows a fixed structural property of the cube rather than
the decomposition in its training data — and would substantially narrow the headline claim from
Parts II–III.
